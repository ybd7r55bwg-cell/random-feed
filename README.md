# 随机流 · 反推荐算法

不学习你、不猜你、不优化你的纯随机短视频信息流。可安装到手机主屏幕，离线可用。

## 算法

每轮对整个候选池做一次**不放回随机排列**（Efraimidis–Spirakis 加权抽样）：
`key = U^(1/w)`，取最大的 key 依次出队。

- **完全均匀随机**：每个视频 `w = 1`，退化为普通随机洗牌 —— 结果是产量大的领域出现得多
- **分层均匀随机**：`w = 各标签 1/该标签出现次数 的平均`，让每个领域总概率质量相等

同一个种子下切换两种方式，随机数序列完全相同，差别只来自权重，是可控对照。

## 为什么审计只看前 15 条

每轮是整个候选池的完整排列，所以**全轮领域分布是固定的**，两种方式算出来必然一样。只有开头这段的分布才反映方法的差异，因此审计窗口取前 15 条。

注意 15 条样本量偏小，单轮波动明显，多换几个种子才准。

## 结构

    index.html      应用本体（竖屏全屏卡片、上下滑动、参数抽屉）
    manifest.json   PWA 安装配置
    sw.js           Service Worker，离线缓存
    icons/          180 / 192 / 512 图标

## 本地预览

双击 index.html 用浏览器打开即可。`file://` 下 Service Worker 不会注册，没有离线缓存，属正常现象。

## 部署

推到 GitHub 后在仓库 Settings → Pages 里把 Source 设为 `Deploy from a branch`、分支 `main`、目录 `/(root)`，等一到两分钟即可获得 `https://<用户名>.github.io/<仓库名>/`。

## 改示例数据

`index.html` 里的 `seedVideos()` 返回 30 条示例候选视频，字段依次为
`id, 标题, [标签], 时长秒, 作者, 发布小时数, 播放, 点赞, 评论`。
标签需取自文件顶部的 `TOPICS` 数组。
